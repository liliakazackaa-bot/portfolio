## 1. Цель и аудитория

### 1.1. Цель
Получать заявки на разработку сайтов, приложений и ИИ-агентов.
**Целевое действие:** отправленная форма или переход в Telegram/на почту.
Портфолио — средство доказательства компетенции, а не цель.

**Критерии успеха**
- Посетитель за 10 секунд понимает: кто, что делает, для кого.
- От любого места страницы до формы — не больше одного клика.
- Lighthouse 95+ по Performance, Accessibility, Best Practices, SEO (мобильный профиль).
- На странице нет ни одной выдуманной цифры, отзыва или клиента.

### 1.2. Целевая аудитория
| Сегмент | Кто | Боли |
|---|---|---|
| Эксперты | Коучи, психологи, консультанты, авторы онлайн-курсов | «Нужен сайт, который продаёт меня», «Отвечаю в директ одно и то же», «Запись клиентов в хаосе» |
| Малый и средний бизнес | Салоны, клиники, сервисы, локальные компании | «Нет заявок из интернета», «Процессы в Excel и чатах», «Менеджеры тонут в однотипных вопросах» |

Общее: им нужен результат, а не технологии. Тексты говорят языком задач, технологии — только в тегах.

### 1.3. Ограничения и решения
- Язык — русский. Одна страница + страница политики ПДн + 404.
- Реальных кейсов и отзывов пока нет → вместо кейсов демо-проекты с явной пометкой «демо»; блок отзывов не выводится.
- Живого ИИ-чата нет → в карточке ИИ-агентов анимированная демонстрация сценария диалога с подписью «пример сценария».
- Заявки уходят на почту через Web3Forms, своего сервера нет.
- Только тёмная тема.

### 1.4. Вне рамок (YAGNI)
Живой чат с LLM, блог, блок отзывов, калькулятор стоимости, мультиязычность, светлая тема, 3D/WebGL, GSAP, Lenis, CMS.

### 3. Проекты
- **H2:** «Проекты»
- Пояснение (моно, `--text-dim`): `// демо-проекты: показывают подход и качество. реальные кейсы появятся здесь по мере запуска.`
- Три карточки в ряд (≥ 900 px) / одна колонка. Каждая: бейдж `демо`, цвет направления, превью-обложка (стилизованный макет экрана из CSS, без внешних картинок), заголовок, «Задача», «Решение», «Что получает клиент», стек-теги, кнопка.

**1. Лендинг для психолога** (сайты, циан)
- Задача: частная практика, клиенты приходят только по сарафанному радио; нужен сайт, которому доверяют и через который записываются.
- Решение: спокойный лендинг с рассказом о подходе, ответами на частые страхи, ценами и формой записи на первую встречу.
- Что получает клиент: понятный путь от первого знакомства до записи без переписки в директе.
- Стек: `Astro` `CSS` `Web3Forms`
- Кнопка: `демо скоро` (текстовая метка без ссылки). Когда у проекта в `site.ts` появляется поле `demoUrl`, метка автоматически заменяется ссылкой `открыть демо ↗` — это правило для всех трёх проектов.

**2. Онлайн-запись для студии** (приложения, маджента)
- Задача: администратор ведёт запись в таблице и мессенджерах, клиенты путаются во времени, бывают накладки.
- Решение: веб-приложение с расписанием мастеров, онлайн-записью для клиентов и напоминаниями в Telegram.
- Что получает клиент: одно место для расписания, клиенты записываются сами, напоминания уходят автоматически.
- Стек: `React` `Node.js` `PostgreSQL` `Telegram Bot API`
- Кнопка: `демо скоро`.

**3. ИИ-агент для онлайн-школы** (ИИ-агенты, лайм)
- Задача: менеджеры тратят день на одинаковые вопросы о программе, ценах и рассрочке.
- Решение: агент в Telegram отвечает по базе знаний школы, подбирает курс под цель ученика и передаёт тёплые заявки менеджеру с кратким резюме диалога.
- Что получает клиент: менеджеры работают только с готовыми к покупке людьми, вопросы закрываются в любое время суток.
- Стек: `Python` `LLM API` `RAG` `Telegram Bot API`
- Кнопка: `демо скоро`.

- CTA под проектами: «Хотите так же для своего дела?» + `[ обсудить проект ]`.

### 6. FAQ
- **H2:** «Частые вопросы»
- Аккордеон на `<details>`, открыт может быть любой набор, по умолчанию все закрыты.

1. **Сколько стоит и от чего зависит цена?** — Ориентиры — в карточках услуг. Итог зависит от объёма: количества экранов, интеграций, сложности логики. После брифа присылаю фиксированную смету, и она не меняется без вашего согласия.
2. **Что если мне не понравится результат?** — Работаем этапами: вы видите макет до разработки и прогресс каждую неделю, поэтому сюрпризов в конце не бывает. Правки в рамках согласованной задачи входят в стоимость.
3. **Можно начать с маленького пилота?** — Да, и это часто лучший вариант. Для ИИ-агентов пилот занимает 1–2 недели: проверяем на реальных клиентах и только потом расширяем.
4. **Чем ИИ-агент отличается от обычного чат-бота?** — Чат-бот ходит по жёсткому сценарию кнопок. ИИ-агент понимает свободные вопросы, отвечает по вашей базе знаний, выполняет действия — записывает, создаёт заявку — и передаёт человеку то, что сам решить не может.
5. **Кому принадлежат код и данные?** — Вам. После оплаты передаю исходный код, доступы ко всем сервисам и права на результат.
6. **Вы работаете по договору? Как платить?** — Да, работаю по договору. Оплата этапами: предоплата за первый этап, дальше — по готовности каждого этапа.
7. **Что происходит после запуска?** — 30 дней бесплатно исправляю ошибки и вношу мелкие правки. Дальше — поддержка по договорённости или разовые доработки.

- Под аккордеоном: «Не нашли ответа?» + ссылка `спросите в telegram ↗`.

## 5. Дизайн-система

### 5.1. Настроение
Интерфейс инженера, который делает вещи, а не презентации: чёрный экран, лаймовый курсор, моноширинные подписи. Дерзко, но аккуратно — акценты точечные, много воздуха.

### 5.2. Цвета (`src/styles/tokens.css`)
| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `oklch(0.14 0.01 160)` / `#060A08` | Фон страницы |
| `--surface` | `oklch(0.20 0.015 160)` / `#101814` | Карточки, поля, аккордеон |
| `--line` | `#1F2A24` | Рамки 1px, сетка, разделители |
| `--text` | `oklch(0.93 0.02 130)` / `#E3EBDD` | Основной текст |
| `--text-dim` | `#8A9A88` | Вторичный текст, подписи |
| `--lime` | `oklch(0.88 0.21 130)` / `#A8F145` | Главный акцент, направление «ИИ-агенты» |
| `--cyan` | `oklch(0.74 0.12 220)` / `#39BCDF` | Ссылки, вторичные кнопки, направление «Сайты» |
| `--magenta` | `oklch(0.68 0.20 330)` / `#D961D2` | Ошибки, 404, направление «Приложения» |
| `--on-accent` | `#060A08` | Текст на лаймовых/циановых заливках |

Правила: лайм — для кнопок, плашек, курсора, статуса и крупных элементов, не для абзацев. Все пары текст/фон — WCAG AA минимум (основной текст — 16.3:1, `--text-dim` на `--bg` — не ниже 4.5:1, проверяется тестом). Каждое направление сохраняет свой цвет в услугах, проектах и чипах формы. `color-scheme: dark`.

### 5.3. Шрифты
| Роль | Шрифт | Начертания | Размер |
|---|---|---|---|
| H1 | Onest | 800 | `clamp(2.5rem, 9vw, 7rem)`, line-height 1.02, letter-spacing −0.02em |
| H2 | Onest | 700 | `clamp(1.75rem, 4.5vw, 3.25rem)`, line-height 1.1 |
| H3 / заголовки карточек | Onest | 700 | 1.375rem |
| Текст | Onest | 400 / 500 | 1.0625rem (17px), line-height 1.6 |
| Служебное: подписи, теги, кнопки, статус, номера | JetBrains Mono | 400 / 500 | 0.8125–0.9375rem |

Шрифты self-hosted через `@fontsource-variable/onest` и `@fontsource-variable/jetbrains-mono`, подмножества `latin` + `cyrillic`, `font-display: swap`, preload только Onest. `text-wrap: balance` для H1/H2.

### 5.4. Сетка и отступы
- Контейнер: `min(1200px, 100% − 2 × 16px)`, по центру.
- Отступ между секциями: `clamp(5rem, 12vw, 9rem)`.
- Шкала отступов: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px.
- Брейкпоинты: 600, 900, 1200 px. Карточки — container queries.

### 5.5. Компоненты и мотивы
- **Подпись секции:** моно, `--text-dim`, вид `// 01 — услуги`.
- **Кнопка главная:** заливка `--lime`, текст `--on-accent`, моно 500, вид `[ текст ]`, radius 2px, высота 48px. Hover: сдвиг тени-рамки на 3px (жёсткая лаймовая «тень» смещается), без размытия.
- **Кнопка вторичная:** прозрачная, рамка и текст `--cyan`.
- **Карточка:** фон `--surface`, рамка 1px `--line`, radius 4px. Hover: рамка цвета направления, угловые скобки по 4 углам, подсветка за курсором.
- **Плашка-выделение:** фон `--lime`, текст `--on-accent`, padding 0 0.15em.
- **Тег:** моно 0.8125rem, рамка 1px, radius 2px.
- **Курсор:** `▊` лаймом, мигание 1s steps(1).
- **Фокус:** outline 2px `--cyan`, offset 3px — у всех интерактивных элементов.

## 6. Обязательные элементы

### 6.1. Форма заявки
| Поле | Тип | Обязательно | Валидация / поведение |
|---|---|---|---|
| Имя | text | да | 2–60 символов |
| Telegram или email | text | да | Email (`x@y.z`) или Telegram (`@` + 5–32 символа `[A-Za-z0-9_]`, или ссылка `t.me/…`) |
| Что нужно | радио-чипы: Сайт / Приложение / ИИ-агент / Не знаю | да | Ровно один |
| Где будет работать агент | радио-чипы: Telegram / Сайт / CRM / Пока не знаю | нет | Показывается только при «ИИ-агент» |
| Задача | textarea | нет | До 1000 символов, счётчик |
| Бюджет | радио-чипы: до 50 тыс / 50–150 тыс / 150–500 тыс / больше / Пока не знаю | нет | — |
| Согласие на обработку ПДн | checkbox | да | Ссылка на `/privacy` |
| botcheck | hidden checkbox | — | Ловушка для спама (Web3Forms honeypot) |

- Кнопки CTA с `data-service` (`site` / `app` / `agent` / `unknown`) при переходе к `#contact` выбирают соответствующий чип.
- Ошибки — под полем, цвет `--magenta`, появляются при уходе с поля и при отправке; поле получает `aria-invalid`, ошибка связана через `aria-describedby`. При отправке фокус уходит на первое поле с ошибкой.
- Отправка: `fetch POST https://api.web3forms.com/submit` (JSON), тема письма «Заявка с сайта: {Что нужно}». Кнопка во время отправки: `[ отправляю… ]`, неактивна.
- Успех: форма заменяется блоком `✓ заявка принята` / «Отвечу в течение дня. Если срочно — напишите в Telegram.» Фокус переводится на блок, статус объявляется через `aria-live="polite"`.
- Ошибка сети/сервиса: под кнопкой `× не удалось отправить. попробуйте ещё раз или напишите на email` (маджента), введённые данные сохраняются.
- Без JavaScript: форма отправляется обычным POST на Web3Forms с `redirect` обратно на `/#contact`.

### 6.2. CTA
Шапка · Hero · каждая карточка услуги · под проектами · под процессом · финальный блок · мобильная закреплённая кнопка. Все ведут на `#contact`.

**Мобильная закреплённая кнопка** (< 900 px): `[ обсудить проект ]` во всю ширину внизу экрана, появляется после ухода hero из видимости, скрывается, когда в видимости секция `#contact`.

### 6.3. Анимации
Все анимации внутри `@media (prefers-reduced-motion: no-preference)`; при reduced motion контент показывается сразу в финальном состоянии. Анимируются только `transform`, `opacity` и регистрируемые `@property`.

| # | Элемент | Поведение | Реализация |
|---|---|---|---|
| A1 | H1 в hero | Текст печатается по символам (~35 мс/символ), затем мигает курсор `▊` | Скрипт оборачивает символы в `<span>`, полный текст остаётся в `aria-label` у H1; без JS текст виден целиком |
| A2 | H1, hover | Вес Onest плавно растёт с 800 до 900 у слова под курсором (≥ 900 px, только устройства с hover) | `@property --wght`, `font-variation-settings` |
| A3 | Появление блоков | `.reveal` поднимаются на 2rem и проявляются при входе в экран | `animation-timeline: view()` под `@supports`; иначе IntersectionObserver добавляет класс `is-visible` |
| A4 | Диалог агента | Реплики появляются по очереди с индикатором «печатает…» (900 мс), старт при попадании карточки в экран, проигрывается один раз; кнопка `↻ повторить` | IntersectionObserver + таймеры |
| A5 | Карточки | Подсветка за курсором и угловые скобки на hover | `pointermove` → `--x/--y`, `radial-gradient` |
| A6 | FAQ | Плавное раскрытие `<details>` | `interpolate-size: allow-keywords` + `::details-content` под `@supports`; без поддержки — мгновенно |
| A7 | Курсоры и статус | Мигающий `▊` у лого, пульсирующая точка статуса | CSS keyframes |
| A8 | Шапка | Фон и нижняя линия появляются после 40px прокрутки | IntersectionObserver на «сторожевом» элементе |

## 7. Техническая архитектура

### 7.1. Стек
Astro (последняя стабильная), TypeScript, ванильный CSS, без UI-фреймворка. `@astrojs/sitemap`, `@fontsource-variable/onest`, `@fontsource-variable/jetbrains-mono`. Тесты: Playwright + `@axe-core/playwright`. Статическая сборка (`output: 'static'`), хостинг — любой статический (Netlify / Vercel / GitHub Pages).

### 7.2. Структура файлов
```
src/
  content/site.ts          — все тексты, заглушки, услуги, проекты, шаги, FAQ, стек
  styles/tokens.css        — цвета, шрифты, отступы
  styles/global.css        — сброс, база, утилиты (.container, .reveal, .tag, .btn)
  layouts/Base.astro       — <head>, мета, OG, JSON-LD, шрифты, skip-link
  components/
    Header.astro  Hero.astro  Services.astro  ServiceCard.astro  AgentDemo.astro
    Work.astro  ProjectCard.astro  Process.astro  About.astro  Faq.astro
    Contact.astro  ContactForm.astro  Footer.astro  MobileCta.astro  SectionLabel.astro
  scripts/
    typewriter.ts  reveal.ts  agent-demo.ts  spotlight.ts  header.ts
    mobile-menu.ts  mobile-cta.ts  form.ts  form-validate.ts
  pages/index.astro  pages/privacy.astro  pages/404.astro
public/  favicon.svg  og.png  robots.txt
tests/   *.spec.ts
```
Принцип: каждый компонент берёт данные только из `site.ts` через props; каждый скрипт — один модуль с одной задачей, инициализируется по `data-*`-атрибуту и ничего не знает о других.

### 7.3. Валидация формы
`form-validate.ts` — чистые функции без DOM (`validateName`, `validateContact`, `validateForm`), покрываются юнит-тестами. `form.ts` связывает их с DOM, отправкой и состояниями.
